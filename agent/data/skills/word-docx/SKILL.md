# Word 文档处理

## 适用场景

当主要产物是 Microsoft Word 文档或 `.docx` 文件时使用，尤其涉及修订批注、页眉页脚、列表编号、域代码、表格、模板或兼容性要求。

## 核心规则

### 1. DOCX 是 OOXML，不是纯文本

- `.docx` 是一个 XML 部件的 ZIP 包，结构与可见文本同等重要。
- 关键部件：`word/document.xml`、`styles.xml`、`numbering.xml`、页眉页脚、关系文件。
- 文本可能被拆分到多个 run 中，不要假设一个词或句子只在一个 XML 节点里。
- 区分三种工作流：结构保留读取（快速阅读）、样式驱动生成（新建文件）、OOXML 感知编辑（修改脆弱的已有文档）。
- 如果任务以阅读/提取/审阅为主，优先走结构保留的读取路径，再考虑触碰 OOXML。
- 深度编辑时检查包布局，不要仅依赖渲染输出。
- `.doc` 属于旧格式，通常需要先转换再做 `.docx` 相关假设。

### 2. 样式与直接格式化

- 优先使用命名样式而非直接格式化，保持文档可编辑。
- 段落样式、字符样式和直接格式化行为不同，要理解层叠关系。
- 移除直接格式化通常比叠加更多行内格式更安全。
- 编辑已有文件时，扩展现有样式体系，而非另起一套。
- 跨文档复制内容会静默引入外来样式、主题设置和编号定义。

### 3. 列表与编号

- 项目符号和编号属于 Word 的编号定义系统，不是粘贴的 Unicode 字符。
- `abstractNum`、`num` 和段落编号属性三者都有影响，重启行为很少是"仅视觉"的。
- 缩进和编号相关但不等同；列表可能缩进正确但底层编号状态已坏。
- 在一个编辑器中看起来正确的列表，换个编辑器可能重新编号、扁平化或重置。

### 4. 页面布局与分节

- 页边距、纸张方向、页眉页脚、页码属于节级行为。
- 首页和奇偶页页眉可以不同，修复一处不代表修复全文。
- 显式设置纸张大小（A4 / US Letter），因为默认值差异会影响分页和表格宽度。
- 用分节符处理布局变化；手动空格和孤立分页符会导致漂移。
- 页眉页脚中的媒体使用部件特定的关系 ID，复制 ID 常破坏图片或链接。
- 表格、分页符和页眉常联动漂移，布局修复应全局考虑，而非局部修补。
- 表格几何依赖页面宽度、页边距和固定宽度，"差不多"的表格编辑在 Google Docs 或 LibreOffice 里常会出问题。

### 5. 修订、批注与域代码

- 启用修订时，可见文本不等于完整文档。
- 插入、删除和批注携带元数据，粗心编辑会保留残留。
- 已删除文本可能仍存在于 XML 中，只是不再显示。
- 批注锚点和审阅范围会因文本移动而断裂。
- 批注标记和审阅包装器不等同于行内格式化，移动文本时可能导致孤立或错位。
- 批注、脚注、书签和链接媒体可能在独立部件中，不全在文档主体里。
- 目录、页码、日期、交叉引用和邮件合并占位符都是域。
- 编辑域源代码要小心，缓存显示值刷新前可能滞后。
- 超链接、书签和引用在 ID 或关系不匹配时会断裂。
- 即使可见文本未变，书签、脚注、批注范围和交叉引用也依赖稳定锚点。
- 修订工作流中应做最小替换，而非重写整段。
- 在法律、学术或商务审阅文档中，默认采用审阅式编辑，除非用户明确要求重写。

### 6. 交付前验证往返兼容性

- 复杂文档在 Word、LibreOffice、Google Docs 和转换工具间可能发生偏移。
- 表格、页眉、嵌入字体和复制样式是常见的布局漂移源。
- `.docm` 含宏，风险更高；`.doc` 是旧格式，可能需先转换。
- 在布局要求严格时，显式表格宽度比自动适应更安全。
- 通过文本检查的文档仍可能在分页、表格宽度或引用刷新后失败。

## 常见陷阱

- 复制粘贴可能引入不想要的样式和编号定义。
- 页眉页脚图片使用部件特定关系 ID，盲目复用 ID 会破坏图片。
- 用空段落做间距会让模板脆弱；间距应设在段落属性中。
- 看似干净的导出仍可能隐藏未解决的修订、批注或过期域值。
- 靠"目视"重启列表通常会失败，因为编号状态存在于段落文本之外。
- 一个可见短语可能跨越多个 run、书签、修订标记或域边界。
- 用替换整段的方式改一处措辞，往往破坏审阅质量、书签、批注或邻近行内格式。
- 删除段落或列表项的所有可见文本后，可能残留空段落标记、空项目符号或不稳定编号。
- 表格自适应和百分比宽度在 Word 中可行，但在 Google Docs 或 LibreOffice 中可能漂移。
- 兼容模式可能静默限制新功能或改变分页行为。
- 纸张大小或页边距的一次改动可能级联影响表格、页眉、目录和交叉引用。
- 审阅工作流可能在屏幕上看起来已接受，但残留元数据、批注或域缓存仍使文件不稳定。
- 目录条目、脚注和交叉引用在收件人更新域后可能暴露断裂的锚点。
