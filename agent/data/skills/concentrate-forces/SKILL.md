# 集中兵力

资源有限时，不要分散力量同时应对多个问题，而要集中优势兵力于主要矛盾，彻底解决一个再转向下一个。伤其十指不如断其一指。

## 不适用场景

**以下情况不需要调用此 skill：**
- 当前只有一个任务，不存在资源竞争
- 用户明确要求同时推进多个任务（用户指令优先）
- 任务是并行独立的，完全没有资源竞争
- 已经在执行选定的主攻任务，不需要重新决策

## 何时使用

你应该在以下情况调用此 skill：

- 面前有多个任务/问题同时需要处理
- 资源有限，不可能同时处理所有事
- 正在同时推进多件事但哪件都做不好
- 需要决定先做什么、后做什么
- 面对一个大问题，需要决定从哪个部分突破

## 方法流程

1. **列出所有待解决问题** — 盘点每个问题的规模、难度、紧迫度、依赖关系
2. **确定主要矛盾** — 用 `contradiction-analysis` 找出解决了就能带动其他问题的关键问题
3. **选择突破口** — 先易后难、先孤后强、先关键后外围。有准备才开打
4. **集中全部力量** — 不分心，追求彻底（不解决一半就转向），快速解决，验证完成
5. **转向下一个** — 短暂总结（→`criticism-self-criticism`），重新评估剩余问题，锁定下一个目标
6. **不打无准备之仗** — 准备不充分先调查（→`investigation-first`），而非冒然行动

## 常见错误

| 错误 | 正确做法 |
|------|---------|
| 同时做多件事 | 集中力量于一个问题 |
| 问题解决一半就转向 | 彻底解决再转向 |
| 先啃最难的骨头 | 先易后难，积累优势 |
| 准备不足就动手 | 先调查研究再行动 |
| 连续作战不总结 | 每战之后短暂总结 |

## 操作规程

当本 skill 被触发时，**输出任务优先级矩阵并宣告主攻方向**：

1. **列出所有待处理任务**（使用 TodoWrite 工具），为每个任务标注：
   - 影响范围：高 / 中 / 低
   - 解决难度：高 / 中 / 低
   - 依赖关系：是否被其他任务所依赖

2. **选择主攻目标**（一次只选一个），优先级标准：
   - 首选："影响范围高 + 被其他任务依赖"
   - 次选："影响范围高 + 解决难度中"
   - 末选："解决难度低"（积累势能）

3. **宣告并锁定**，格式：
   ```
   🎯 当前主攻目标：[任务名]
   原因：[一句话说明为何优先此任务]
   完成信号：[什么情况下认为完成]

   暂缓任务：
   - [任务B]：[为何暂缓]
   - [任务C]：[为何暂缓]
   ```

4. **执行期间的规则**：
   - 用户中途提出新需求 → 在当前主攻目标范围内？是→纳入，否→记录到 Todo 后处理
   - 主攻目标完成并验证后，才转向下一个目标

## 与其他 skill 的关系

- **矛盾分析法**：确定主要矛盾就是确定集中兵力的方向
- **调查研究**：不打无准备之仗的前提是调查研究
- **持久战略**：在持久战的每个阶段内，用集中兵力原则解决具体问题
- **星火燎原**：建立根据地本身就需要集中兵力
- **批评与自我批评**：战役间隙的总结就是自我批评
