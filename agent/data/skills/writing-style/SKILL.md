# 写作风格精髓

六条从实践中提炼的通用写作原则。不限文档类型，不限行业场景。

---

## 一、定位先于动笔

写之前先回答三个问题：

- **给谁看？** 决定了用词深度和背景铺垫
- **态度是什么？** 请求、建议、汇报、反思、说服——态度决定语气
- **读完希望对方做什么？** 没有行动预期的文档是自说自话

**态度决定语气的例子**：

| 态度 | 语气特征 |
| ---- | -------- |
| 请求 | 谦逊、给对方选择空间 |
| 建议 | 有观点但不强加，承认其他可能性 |
| 汇报 | 客观、结论先行、不邀功 |
| 反思 | 诚实、不回避困惑 |
| 说服 | 有论据、有对比、不煽情 |

**检验**：如果把文档的第一段单独拿出来，读者能判断出这是请求还是汇报吗？

---

## 二、结论前置

最重要的东西放最前面。不要让读者猜。

**不同场景的前置模式**：

- **汇报**：一句话概述当前状态，有问题先说问题
- **请求/提案**：第一段就说"希望对方做什么"
- **设计文档**：开篇是"本文档回答一个核心问题：**...**"
- **博客/分享**：用痛点或问题建立共鸣，预告文章价值
- **邮件**：主题行即结论，正文第一句是行动项

**反面案例**：铺垫三段背景才进入正题——读者在第二段已经走神了。

**检验**：读者只看前三行，能知道这篇东西要说什么吗？

---

## 三、诚实 > 完美

承认局限是专业的表现，不是软弱。全是好消息的文档不值得信任。

**怎么做**：

- 主动暴露风险，而非等问题暴露后再解释
- 承认方案的代价和权衡，不假装没有代价
- 明确列出"非目标"或不讨论的范围
- 不确定的事，直说"我的判断是...，但不确定"
- 留一个"未解决的问题"或"已知局限"章节

**检验**：这篇文档有没有"我不知道"或"还没解决"的部分？如果通篇都是正面信息，要么是真的完美（概率极低），要么是在回避。

---

## 四、讲故事，不罗列

人脑记住故事的效率远高于列表。

**差**：

```markdown
系统特点：1. 轻量 2. 按需创建 3. 支持顺序消费
```

**好**：

```markdown
传统方案像是租了一整间办公室——用不用，位置都在那里占着。
新方案像是共享工位——用的时候坐下来，用完就走。
```

**可用的叙事技巧**：

- **类比**：把抽象概念映射到日常经验
- **对比**：直觉 vs 实际、旧方案 vs 新方案、理想 vs 现实
- **时间线**：用 t1, t2... 演示过程、问题的发生顺序
- **场景还原**："想象你是一个刚接手项目的新人..."
- **矛盾**：先说一个看似合理的观点，再翻转它

**检验**：这段话能不能在饭桌上讲给朋友听？如果不能，说明还不够"故事化"。

---

## 五、克制即风格

好文字的特征往往不是"加了什么"，而是"忍住没加什么"。

**语气**：

- 短句为主，段落短（1-3 句）
- 不煽情、不感叹号、不自吹、不说教
- 情感通过思考的深度体现，而不是直接表达
- 自信但不傲慢，谦虚但不卑微

**内容**：

- 不堆砌细节——汇报不是工作日志，设计文档不是代码注释
- 不流水账——按主题组织，不按时间线记流水
- 关键结论加粗或引用，其余保持平实

**禁忌清单**：

- 感叹号泛滥
- 煽情表达（"令人振奋""激动人心"）
- 空泛修饰词（"浅谈""初探""详解""深度解析"）
- 口语过渡词滥用（"其实""说实话""坦白讲""众所周知"）
- 不必要的自我指称（"笔者认为""作为一个..."）

**检验**：把所有形容词和副词删掉，意思变了吗？如果没变，那些词就是多余的。

---

## 六、自由度适配

不同场景需要不同程度的发挥空间。写作的失败往往是自由度错配。

| 自由度 | 典型场景 | 策略 |
| ------- | -------- | ---- |
| **低** | 周报、状态更新、Bug 报告、会议纪要 | 严格按模板，不发挥 |
| **中** | 设计文档、提案、API 文档、反馈 | 遵循结构骨架，内容自由 |
| **高** | 博客、演讲稿、深度分析、年度总结 | 守住原则，形式自由 |

**常见错配**：

- 周报写成散文（低场景用了高自由度）
- 博客写成模板填空（高场景用了低自由度）
- 提案全是观点没有结构（中场景缺了骨架）

**检验**：这篇东西的形式感，和它的重要性 / 创作空间匹配吗？

---

## 排版基线

无论写什么，以下规则始终适用：

- 中英文之间加空格：`正确 Example 示例`
- 中文与数字之间加空格：`共 10 个`
- 标题后空一行再写正文
- 代码块指定语言，前后空一行
- 专有名词大小写正确：GitHub、JavaScript、macOS
- 中文使用全角标点
- 链接文字要有意义，不用"点击这里"

---

## 快速自检清单

写完任何东西后过一遍：

- [ ] 前三行能看出要说什么
- [ ] 态度和语气与场景匹配
- [ ] 有承认局限或不确定的部分
- [ ] 关键信息用类比或对比呈现，而非干巴巴罗列
- [ ] 没有感叹号、煽情、自吹
- [ ] 中英文之间有空格
- [ ] 形式的正式程度与场景匹配
