# 文档格式决策

选择载体时，看接收方的阅读体验和后续要做的事，不要只看用户最先提到的文件类型。

在 IM 里，只有内容确实容易直接阅读时，才默认用简短文字回复。如果直接发 IM 会变成长篇文字、密集表格、难跟的流程，或无法快速扫读的解释，就主动选择更合适的产物：图片、文件、临时 HTML 页面、电子表格、文档、演示文稿或 PDF。

## 语言规则

默认使用中文。

- 载体判断、IM 摘要、产物标题、标题层级、标签、正文、表格、备注和下一步说明都应使用中文。
- 专有名词、产品名、代码标识、文件扩展名、API 名，以及 Word、Excel、PowerPoint、PDF、HTML、Markdown、CSV、JSON 等通用术语，在保留原文更清楚时保留原文。
- 只有当用户明确要求、源材料必须保留原文，或接收方明确需要非中文交付物时，才使用其他语言。

## 核心规则

先问两个问题：

1. “人能不能舒服地在 IM 里读完？”
2. “接收方接下来要拿它做什么？”

- 现在读、快速回复：用 IM 文字。
- 在聊天流里快速扫结构化摘要：用图片/卡片。
- 浏览丰富版式、交互演示、动画、时间线、仪表盘或视觉解释：用临时 HTML 页面。
- 审阅、修改、审批、打印、签署或归档长文：用 Word，必要时再导出 PDF。
- 计算、比较、筛选、报价、预算、排期或建数字模型：用 Excel。
- 演示、说服、对齐会议室、给领导做视觉汇报：用 PowerPoint。
- 固定版式，用于外发、打印、签署或归档：用 PDF。
- 在系统之间交换原始结构化数据：用 CSV 或 JSON。
- 起草后续要粘贴到其他工具里的内容：用 Markdown。

## IM 主动触发条件

只要出现以下情况，就可以主动创建或提供产物，不必等用户明确说“做个文件”：

- 用户说：“整理一下”“沉淀一下”“发群里”“给领导”“给客户”“汇报”“方案”“报价”“预算”“清单”“排期”“会议纪要”“复盘”“论文”“公文”“合同”“制度”“可打印”“可转发”“留档”。
- 答案会超过一屏手机，包含很多分支，或需要用户滚动后自己在脑中重组结构。
- 信息天然包含章节、表格、附录、版本历史、卡片、图表、时间线、流程、地图或前后对比。
- 会有多人审阅、转发、审批、签署，或后续反复查阅。
- 内容来自零散聊天、附件、笔记或原始数据，真正任务是产出一份干净的交付物。
- 数字必须保持可编辑，并在假设变化时重新计算。
- 版式、字体、分页、图表、动画、交互或视觉层级会影响结果是否好用。
- 用户是在以员工、学生、顾问、销售、项目经理、财务、HR、法务、运营或研究者身份为别人产出工作材料。

判断把握高时，直接创建产物，并附上一句 IM 摘要。只有载体选择确实有歧义时，才问一个简短问题。

## IM 可读性标准

不要因为纯文字输出最容易，就让用户在 IM 里阅读重要的长内容。

出现以下情况时，优先选择产物：

- 内容超过一屏手机。
- 超过 5-7 条要点。
- 表格宽于 3 列，或长于 8 行。
- 流程包含多个步骤、分支、状态、依赖或例外。
- 涉及多个受众、版本、假设、风险或行动负责人。
- 视觉概念用图示、卡片、图表、时间线或交互视图更清楚。
- 用户很可能会展示、转发、保存、比较、编辑或复用这份内容。

这时发送一条简短 IM，例如“我整理成一个页面/表格/文档了，方便看和转发”，再附上产物。

## 载体选择

| 载体 | 适合场景 | 避免场景 |
|---|---|---|
| IM 文字 | 简短回答、快速决策、确认、澄清、复用价值低 | 内容很长、正式、数字密集，或可能被转发 |
| Word `.docx` | 正式长文、论文、公文、报告、合同、SOP、会议纪要、制度、需求、审阅批注流程 | 核心价值是计算、筛选或视觉演示 |
| Excel `.xlsx` | 报价、预算、定价、排期、库存、对比矩阵、数据清洗、情景模型、公式、图表 | 结果主要是叙述文字或最终不可变长文 |
| PowerPoint `.pptx` | 领导汇报、销售材料、提案、路线图、培训、工作坊、项目对齐、故事型解释 | 用户需要的是详细参考文档或可编辑计算表 |
| PDF | 最终外发版本、打印、签字、归档、固定版式、合规、公开分发 | 用户还需要大量编辑、计算或共同协作 |
| 图片/卡片 | 群聊公告、KPI 快照、海报、简单视觉摘要、社交分享 | 内容需要精确编辑、公式、引用或无障碍访问 |
| 临时 HTML | 交互解释、动画、仪表盘、时间线、流程图、丰富视觉摘要、可点击原型、适合通过版式和导航承载的密集内容 | 接收方需要正式可编辑 Office 文件、离线归档或可靠打印效果 |
| Markdown | 草稿、技术文档、笔记、要粘贴到其他系统的内容、轻量协作 | 页面版式、Word 兼容性或打印保真度重要 |
| CSV | 简单表格导入导出、数据交换、系统交接 | 需要格式、公式、多工作表、图表或解释文字 |

## 丰富展示选项

不要把所有东西都强行塞进 Office 文件，要使用系统已有能力：

- 图片/卡片：适合一屏内的视觉摘要、公告、快速状态、排名、清单、海报或可分享快照。
- 临时 HTML：适合交互或动画解释、原型、仪表盘、时间线、复杂对比、流程演示，以及能通过响应式布局提升阅读体验的内容。
- Word/PDF：适合正式阅读、打印、审阅、签署、官方交付和长文。
- Excel：适合必须保持可编辑、可重新计算的数字内容。
- PPT：适合有人要向他人演示观点。

HTML 默认不是“网站”。在 IM 场景中，它可以只是一个临时产物，用折叠区、标签页、卡片、图表、动画、截图或小型交互演示，让内容更容易读。

## 像人一样判断

### 工作与商业

- “方案”如果是书面提案，用 Word；如果要上台讲，用 PPT；如果主要是时间线、资源和成本，用 Excel。
- “报价”通常先做成 Excel，保留公式和假设；只有最终给客户的版本才导出 PDF。
- “会议纪要”如果只有三条要点，留在 IM；如果包含决策、负责人、风险、背景，或需要转发，就用 Word。
- “周报”可以是 IM 快速更新，也可以是正式 Word；领导同步可用 PPT；如果指标和表格占主导，用 Excel。
- “对比”如果要评分或筛选，用 Excel；如果要论证取舍，用 Word；如果要说服一群人，用 PPT。
- 密集解释如果通过渐进展开、标签页、图示、动画或交互示例能明显更好理解，就用临时 HTML。
- 简短公告或结果快照，如果用户希望群里快速读懂，就用图片/卡片。

### 学术与研究

- 论文、文献综述、毕业论文大纲或正式作业，通常应做成 Word，并包含引用、标题层级、排版和页面布局。
- 研究数据、实验日志、问卷结果和统计摘要，应先用 Excel 或 CSV，再把图表和表格放入 Word 或 PPT。
- 答辩、研讨会或研究进展更新，应做成 PPT，使用适合讲述的叙事和视觉层级。
- 最终不可变提交版或分发版应导出 PDF，同时保留可编辑源文件。

### 行政、法务、HR 与运营

- 通知、政策、规则、表单、纪要、合同、函件和正式声明，通常属于 Word，并最终导出 PDF。
- 花名册、考勤、薪资/奖金计算、资产清单、采购、预算和对账属于 Excel。
- 培训、入职、流程说明和跨团队对齐，通常适合 PPT。

### 销售、咨询与客户工作

- 调研记录和客户需求，如果需要正式留档，用 Word。
- 定价、SKU 对比、ROI、TCO、物料清单和实施预算，用 Excel。
- 提案、演示、执行摘要和解决方案简报，用 PPT。
- 客户最终外发版本，通常在审阅后导出 PDF。

## 什么时候不要创建文件

不要因为有 Office 工具，就创建文档。

以下情况留在 IM：

- 用户问的是快速事实问题或简单改写。
- 下一步是澄清，不是交付。
- 内容还太不确定，不适合正式化。
- 信息敏感或临时，除非用户要求，否则不应持久化。
- 创建文件会比直接聊天更拖慢进度。
- 产物只是一屏答案，没有复用价值。
- 用户正在头脑风暴，精致产物会打断交流。

## 产物组合

正确答案经常是一组产物：

- 可编辑源文件 + 最终版本：Word/PPT/Excel + PDF。
- IM 摘要 + 附件：聊天里给一句结论，完整产物放附件。
- IM 摘要 + 临时 HTML：聊天里给简短结论，丰富交互视图放链接或文件。
- IM 摘要 + 图片/卡片：聊天里给一句说明，视觉快照便于快速扫读。
- Excel 模型 + Word/PDF 说明：数字保持可编辑，叙述保持可读。
- PPT + 附录 Excel/Word：演示保持聚焦，证据留在附录。

除非用户明确只要最终 PDF，否则优先保留可编辑源文件。

## 执行指引

1. 判断载体，只在有帮助时简短说明理由，例如：“这个适合做成 Excel，因为后面要改单价并自动算总价。”
2. 按载体构建内容结构：
   - Word：标题、日期/版本、受众、标题层级、表格、引用、正式排版。
   - Excel：输入项、假设、计算表、输出、图表、校验、零公式错误。
   - PPT：叙事线、结论式页标题、视觉层级、图表/图片、演讲节奏。
   - PDF：如果后续可能编辑，先做源产物，再导出固定最终版。
   - 图片/卡片：单一信息目标、强层级、手机上可读。
   - HTML：响应式布局、导航、渐进展开；图表和动画只在确实提升理解时使用。
3. 使用 `office-suite-tools`、具体格式 skill、图片生成/设计 skill 或网页产物工具创建、检查、渲染并验证产物。
4. 在 IM 中，用一句短消息说明这是什么，以及接收方下一步该做什么。

## 反模式

- 明明文档更容易审阅，却发送 IM 长篇文字。
- 明明图片、HTML 页面、表格或文件能降低阅读成本，却发送 IM 长篇文字。
- 把应当在 Excel 中重新计算的定价模型做成 Word。
- 用户后续需要编辑源文件，却只发送 PDF。
- 用户需要参考文档，却创建 PPT。
- 临时 HTML 能更快传达交互或视觉想法时，却创建正式 Office 文件。
- 内容需要签署、打印或在 Office 中编辑时，却创建 HTML。
- 把“整理”只理解成总结，而忽略真正需求是可复用产物。
- 下游任务已经足够明确时，还反问用户想要什么文件类型。
